# E2EE B — local owner change-page AEAD codec (source-only)

`localOwnerPageCodec.ts` provides a Scratch-project-locked client-side codec for an eventual encrypted local mirror of authenticated owner change pages. Its caller must first pass the server-authenticated `listAndDecryptOwnerChanges` and session gate. It re-derives every opaque server row ID from the unlocked root and original owner/domain ID, refuses unknown fields/owner mismatches, then re-encrypts the *entire* owner-local document including the semantic ID and day fields under a new random local revision with separate `local-cache` HKDF domain. Versioned AEAD additional data binds exact project/owner, opaque row, source domain and revision, server timestamp, key ID and local revision. Serialized output exposes only these necessary routing identifiers and ciphertext; tests prove no task title, original ID, memo or date remains in plaintext.

This **does not write IndexedDB** or implement local CAS/idempotent page application, session/root unlock UI, normal RxDB sync, private media, encrypted disaster recovery, complete old-PWA migration or Production release. A future persistent page applier must atomically write a whole page, reject stale revisions and commit server cursor only after durable ciphertext readback. Source-only; real account data must never be used. Track #1662/#2084.

## Durable local IndexedDB ciphertext-only page applier (2026-11-26)

`ownerLocalCipherMirror.ts` provides a concrete isolated-Scratch **ciphertext-only** page applier for `OwnerFeedPageApplier`: all source records are separately sealed under the local-cache domain before entering a single IndexedDB readwrite transaction, with an exact owner/project/collection/opaque-row key. A page transaction is all-or-nothing; an identical server timestamp+revision is idempotent after lost checkpoint acknowledgment, older revisions and same-timestamp conflicts abort. `readLocalCipherOwnerRecord` demands local AEAD readback with the same owner/root/key epoch. The real Chromium test verifies the database contains no title/semantic ID/task date, survives browser reload, rejects wrong-root/cross-owner and older revisions, and makes zero Appwrite writes. This remains disconnected from normal RxDB and does not complete historical PWA snapshots, encrypted media migration or account cutover.

## Fully synthetic owner-change → ciphertext mirror → checkpoint browser rehearsal

`tests/e2e/e2ee-owner-change-to-local-cache.spec.mjs` exercises the real authenticated owner-change decoding API with a disposable in-memory Appwrite-like RPC response. It injects a checkpoint CAS failure **after** the ciphertext mirror has atomically persisted the owner record; the next attempt must reapply idempotently and successfully advance the server-timestamp/opaque-row cursor without skipped changes. After a genuine browser reload, both ciphertext-decoded record and cursor must persist, unrelated owner reads return empty, and no actual Appwrite requests are permitted. The test models a lost local checkpoint acknowledgement rather than making any remote mutation. Still no normal RxDB integration, real historical PWA recovery, completed private media or Production authorization.

## Corruption and concurrency fail-closed review

Before any new page replaces an existing local ciphertext row, the applier now authenticates that older row with the currently unlocked owner root, saves the observed raw bytes, then compares them again inside the atomic write transaction. If the row was tampered with, its project/key epoch changed, or a concurrent tab updated it between preflight and CAS, the *whole page aborts*. After successful transaction commit, it independently decrypts each stored owner row and compares all source fields before returning; only then may the external change-feed checkpoint advance. A real Chromium test corrupts an existing AES-GCM envelope and proves that a newer source revision cannot overwrite it silently. This still does not provide device hardware isolation, a verified old-PWA backup, trusted group messaging or a normal production rollout.
