# #2084 source-only owner pending image rescue — current-dev ancestry

A strictly optional `ownerPendingImageRescue.ts` reads the current-origin `mosaic_pending_images/images` IndexedDB through a **read-only transaction**, including owner-scoped `localimg_` media not referenced by any live task or Diary record. It refuses a missing/uninitialized DB instead of creating an empty one. Bound inventory: <=10,000 total cursor visits, <=500 owner rows and <=64 MiB total owner source data; malformed owner data, duplicate IDs or account change fail the full export. A root+MFA-ready caller must supply an authenticated owner gate. SHA-256 of each owner image is compared across independent source scans before success.

Each owner's photo Blob is encrypted locally with the existing chunked AES-256-GCM media codec; the original `localimg_` ID/created timestamp/owner ID are independently sealed in AEAD under the `attachment-manifest` domain with a fresh opaque row ID and revision, bound to the sealed media ID. No plaintext source ID, MIME or content in the serialized envelope. Local decryption verifies metadata and ciphertext. Synthetic unit negatives cover wrong account/root, changed scan, duplicates and tampering.

**NOT a complete encrypted historical PWA backup:** no runnable UI, disk save/restore, normal RxDB/tombstone/message/backup capture, file packaging, real browser IndexedDB transaction integration or multi-tab freeze; each Blob may be readable only from the exact original browser origin. An installed old PWA cannot be patched retroactively, and a cross-scan ABA race remains possible. This library is dormant; there are no network calls or backend changes. Keep Preview/dev/main/Production unchanged until complete source, backend and independent acceptance.
