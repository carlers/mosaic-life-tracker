# E2EE Phase B: durable encrypted photo replay from a saved rescue File

Tracking #1662 / #2084. Dormant, Scratch-project-pinned source work only, not cloud upload or server ACK.

readVerifiedSealedMediaFromRescueFile verifies the ENTIRE original three-part saved rescue manifest (all owner rows, media and queued social actions) using account-root AEAD authentication, then returns only the EXACT ORIGINAL encrypted media envelope and Blob bytes from the saved File. It does not regenerate randomized media IDs/IVs on retry.

stageSelectedSavedOwnerEncryptedMedia accepts a deliberately reselected File of the required name, checks the externally trusted owner/MFA/root gate, authenticates source media and persists original encrypted bytes and metadata to a dedicated IndexedDB. A root-HKDF/HMAC blind index prevents plaintext owner photo IDs from appearing as database keys. All pre-existing owner media intents must be present and exactly unchanged in a selected saved File. Another export of the same local photo with different randomized ciphertext FAILS CLOSED rather than creating duplicate remote IDs. New staged photos use ONE IndexedDB readwrite transaction, byte-by-byte comparisons of pre-existing ciphertext and full AEAD on readback. A quota, conflict or second-add failure aborts all additions. No local source, saved File or pending ciphertext is deleted, acknowledged, or re-encrypted.

readStagedOwnerEncryptedMedia reauthenticates owner, root, ciphertext bytes, photo metadata and account after reload. The synthetic browser test includes actual download/reselection of an encrypted saved File, two owner photos and a foreign photo, source tampering and wrong-key rejection, IndexedDB privacy inspection and a simulated lost remote response with original media IDs/bytes retained.

Limits: the existing normal app photo upload remains plaintext before E2EE activation. No real encrypted bucket/Function/receipt, no provider Storage upload, no cross-tab source freeze, no old PWA write cutoff and no cross-store account-wide atomic cutover are provided. Local browser storage can be evicted. An off-device saved authenticated rescue and independent high-entropy recovery key remain mandatory. Never enable upload, clear/ACK a pending record, or promote dev/main/Production until protected Oracle CI, installed Appwrite root-generation CAS and future reviewed server media contracts pass.

## Synthetic ciphertext transport readback (dormant)

ownerSavedMediaTransportRehearsal.ts rehearses an explicitly injected in-memory PUT/GET adapter against a previously authenticated local opaque photo intent. It sends only the sealed metadata and ciphertext Blob, requires strict response status and exact ID/key/revision/manifest/ciphertext byte equality, independently opens the returned AEAD and rereads the retained IndexedDB intent. Lost responses, nonliteral status, wrong metadata, altered bytes and a session gate failure must reject. No plaintext local photo ID or root is sent. The gate must independently verify the current owner/MFA/root; this media queue does not persist root generation. The adapter is NOT an Appwrite Storage contract, server receipt, atomic epoch fence or permission to acknowledge or delete any intent. No active transport, backend writes, normal app import, release or version impact.
