# Strict offline rescued-owner to v2 staging boundary

Tracking app #1662/#2084. Dormant source-only helper stageVerifiedScratchRescueOwnerV2 bridges a **previously verified and decrypted** same-project encrypted local rescue file to first-write-wins HMAC-authenticated IndexedDB plans. No Appwrite requests, remote receipts, account migration, queue/media replay, local source modification, or old installed PWA support.

The helper fails closed **before any pending intent write** when any protected row belongs to friends/chat or any pending outbox/media exists, or when any one raw row has unknown fields, wrong owner, invalid revision, malformed physical tombstone state, or duplicate opaque ID. It refuses a saved rescue that omits a previously staged pending row; a subset must never impersonate a complete cutover. Only the eight strictly classified private owner domains may be staged and each must roundtrip through v2 authenticated AEAD. Physical RxDB deletion remains a server-visible boolean tombstone without revealing task title, diary content, date or visibility.

The helper does not clear or acknowledge queued records; retries converge to previously staged original operation IDs and ciphertext, including across a browser reload. Local IndexedDB storage is not a durable user-saved backup. On failure after some local staging, the original source and encrypted saved file remain untouched and are required to retry. Global multi-tab source snapshot, historical PWA origins, authentic current root/epoch, v2 signed Function authorization, server CAS/write fence and all social/media migration remain blockers. No Preview/dev/main/Production mutation or E2EE launch is authorized.
