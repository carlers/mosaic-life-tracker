## Manual overlay: collision regression resolved (Nov 24)

Source-level review of official `@dnd-kit/react@0.5.3` `DragDropProvider.tsx` confirmed callbacks have **`(event, manager)`** signature. The event's `operation` is a snapshot; moving that object does not update live collision state. `@dnd-kit/dom@0.5.3` Feedback also updates live `dragOperation.shape` per movement. Removing Feedback froze collisions in the original category even when the user's pointer was over the destination. The renderer now writes an inexpensive translated `Rectangle` to **`manager.dragOperation.shape`**, from a single source rect captured at pickup, as well as moving the visual with native pointer events. It imports `@dnd-kit/geometry` directly, so its already-locked 0.5.3 package is now declared as an explicit direct dependency in this **diagnostic-only** branch; no transitive dependency versions or application state/backend changed.

[Exact isolated functional browser run #45463783222](https://github.com/carlers/mosaic-life-tracker/actions/runs/45463783222) **SUCCESS**:
- Three same-gesture controls (`baseline`, `scoped`, `manual-overlay`) all showed a category-1 insertion gap when moving `profile_task_0` to `profile_task_3`; the pointer hit category1 and source slot remained registered.

- Escape cleanup and source restoration validated in all three controls. This verifies **synthetic cross-category projection and cancellation**, not a persisted backend reorder, mobile touch, grouped diary or single diary. These remain owner/manual acceptance gates.
