# E2EE B — Scratch-only encrypted owner change-feed checkpoint (source-only)

`ownerChangeFeedCheckpoint.ts` stages client-verified `listAndDecryptOwnerChanges()` change pages behind an injected *durable idempotent* local page applier and *compare-and-set* cursor store. Each checkpoint binds the exact Scratch project ID, owner, collection, root key ID and generation, and the server-owned timestamp + opaque row ID. Every page is already locally AEAD-validated by the existing owner transport. The adapter checks authentication/owner scope before and after awaited operations and only commits a checkpoint **after** an explicitly idempotent local page apply. It halts on wrong owner/key/epoch, expired authentication, a failed local apply, or a CAS race; retry may reapply an earlier page but must never skip it. Existing collection transport authenticates cursor monotonicity and rejects tampered ciphertext. Limit of 25 pages/pass returns `moreMayRemain:true` rather than pretending a truncated scan is complete.

**Still blocked for normal sync:** No actual RxDB collection applier or production schema, no offline local cursor implementation, no completed media migration, no old client cutoff/read-only rehearsal, no multi-device identity authorization, no normal application encryption enablement or user-testable Preview. A caller that does not provide atomic/idempotent owner-safe `applier.apply` is unsafe and must not be wired into production. This source-only contract does not prove completeness, prevent old plaintext writes or replace authentication. Dedicated Scratch project only. Track #1662 #2084.

## Browser IndexedDB CAS implementation

`ownerFeedIndexedDbCheckpoint.ts` implements the injected checkpoint-store interface with a separate `mosaic-e2ee-owner-feed-cursors-v1` IndexedDB object store. Scope keys use the exact isolated Scratch project/owner/collection tuple. A single readwrite transaction reads the observed checkpoint and applies a monotonic compare-and-set, rejecting stale/replayed timestamps or wrong key generations. Corrupted account metadata fails closed and is not silently discarded. Store holds routing-only metadata, **never** root bytes, document content or plaintext media. Real Chromium/Playwright tests verify no backend writes, cross-account isolation, atomic stale-CAS denial and persistence across actual page reload. This still has no live normal RxDB page applier and must not be promoted or treated as completed encrypted sync.
