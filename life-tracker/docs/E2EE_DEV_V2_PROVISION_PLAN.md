# E2EE isolated Scratch v2 schema migration plan (source-only)

Tracking #1662 / #2084 / private Oracle #295. A **pure read-only** planner, scripts/e2ee-owner-v2-provision-plan.mjs, now prepares the exact additive v2 ciphertext table schema as a deterministic list of proposed actions. This is intended to reduce manual retry loops when the private Oracle CI/root attestation gate is restored. The planner is NOT installed as a migration, does not call Appwrite with credentials, has no CLI or POST and cannot mutate any project.

Only the exact isolated Scratch project 6b00671500279e901846 and life_tracker database are accepted. The caller-supplied read capability receives only GET requests. Existing owner-v1 and root-v2 tables must retain empty table ACLs, row security enabled and expected IDs. Missing v2 generates the exact create_table, 12 required columns and owner-cursor index proposal. A partially provisioned v2 is rechecked against **exact subsets** of the Git-owned frozen schema, rejecting all extra/duplicate columns or indexes, changed types/sizes, broad ACLs and not-available metadata. Only missing reviewed columns/indexes are proposed in order; an already matching schema yields zero actions, not permission to activate a Function. No destructive repair, downgrade, cross-project transfer or data migration is represented.

An actual privileged release worker would still need: private Oracle PR #386 exact-head protected CI; host-installed Appwrite runtime/version attestation; verified synthetic transaction **root-generation concurrency** safety or a separately reviewed serialization architecture (upstream appwrite/appwrite#14489 remains open); an approved migration owner/operator; exact-schema create with per-column/index ready polling, independent GET/ACL readback and an explicit checkpoint journal; signed v2 Function with real MFA+owner authorization and old-client plaintext writer floor. In particular, generating a plan **does not** make the missing table present or unblock E2EE. Preview, dev, main and Production remain unchanged.

## 2026-11-28 root-claim counterpart and combined review packet

`planScratchRootClaimSchema` in `scripts/e2ee-root-claim-provision-plan.mjs` independently GET-attests the existing owner v1/root tables and returns only additive proposed actions for the **disabled** `owner_root_epoch_claims_v2` table. It refuses any active claim table, broad permissions, extra or duplicate columns/indexes, unavailable schema status, drifted security settings, or a wrong project. The closed root-claim table has eight reviewed metadata columns plus a generation index; its contents must never contain a root, recovery secret or proof bytes.

`planScratchV2WithRootClaim` composes the original v2 ciphertext table planner and this root-claim plan into one immutable, **read-only** two-table action set, without skipping either independent baseline/ACL validation. Both modules are unregistered, carry no credentials and issue **GET only**. A planned or matching disabled claim table is *not executable transaction readiness*. Later, a separately approved Git/CI-pinned privileged operator must create missing resources in order, verify their readiness/ACLs by GET, prove installed Appwrite transaction semantics and authenticated owner root proof, activate only the approved isolated Function, and demonstrate old-client write denial. This preparatory plan does not authorize opening the disabled claim table, enabling a Function or promoting any environment.
