# Dormant Scratch current-origin RxDB to saved rescue to encrypted local staging bridge

This source-only bridge unifies E2EE milestone B: ownerCurrentOriginRescueBridge.ts is the first explicit integration entry point bound to real current-origin RxDB 17 storage, its pending-image IndexedDB and social-outbox localStorage. It does not import into normal Mosaic login, UI, replication or Function paths.

buildScratchCurrentOriginRescueFile(root, owner, keyId, gate) reads all ten current owner-local RxDB collections using the raw RxDB storageInstance rather than find() (which hides internal _deleted:true tombstones). It also captures orphan bucket links, all staged images and all owner-scoped queued social work. Missing collection/storage, missing pending images database, unsupported storage query, invalid owner/root/MFA, malformed provenance, mid-capture observed changes or any unsupported source fail closed. The full manifest and each row/media/outbox are AEAD-authenticated; a final source reread runs before the in-memory Blob is returned. No backend request occurs. The optional database parameter is only for isolated tests on actual RxDB storage; unlike a custom row reader it cannot pretend absent collections contain nothing.

Two distinct, non-optional user actions remain: download/save mosaic-local-rescue-v2.enc and explicitly reselect that same file. stageSelectedScratchOwnerRescueFile accepts only a browser File of the expected name, rechecks an externally trusted owner MFA/unlocked-root gate and verifies the complete selected encrypted manifest before an atomic first-write-wins owner-v2 IndexedDB staging transaction. The wrapper cannot tell whether the user actually retained an off-device copy; a file name is not cryptographic proof, but the manifest binds contents/root/owner. No staged local ciphertext gets acknowledged or deleted.

Actual browser test: use a completely separate temporary Dexie-backed RxDB instance with all ten collections, real _deleted:true internal task tombstone, a live Diary entry, and a foreign-owner record. Capture from that instance plus an actual initialized image IndexedDB; save and select the encrypted download in Chromium; verify no plaintext ID/title/date in saved file; stage into original owner-HMAC authenticated IndexedDB intents; then a synthetic Function-shaped port proves original opId/ciphertext survived a lost response and page reload. No real Appwrite network and no active Mosaic database is modified.

This is not live encrypted sync: the account's historical old PWA service worker, offline/queued old replication, media upload, server v2 schema, root-generation transaction safety, MFA Function and complete social migration remain excluded. The bridge is dormant, Scratch-project pinned, does not disable normal plaintext replication or connect an Appwrite port, and must not be enabled until those stronger gates and complete user-data portability prove safe. Normal Preview/dev/main/Production unchanged.
